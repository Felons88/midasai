# Expansion Finalization Hang Fix - 2026-07-01 18:34:21

## Issue Analysis
The ExpandOverlay component in `components/architect/ExpandOverlay.tsx` had a handleFinalize function that included a timeout mechanism to prevent hanging when the AI generation process stalls or doesn't complete properly. However, users reported that the expansion overlay would sometimes hang with "step still running" indicating the timeout wasn't working effectively in all cases.

## Root Cause
After analyzing the code, the issue was in the stream handling logic where:
1. The timeout mechanism existed but didn't properly cancel the stream reader in all error paths
2. When the stream ended without an explicit "complete" event, there was a race condition
3. The finally block didn't always ensure proper cleanup of the stream reader
4. Error handling for timeouts wasn't providing clear user guidance

## Fix Implemented
Enhanced the handleFinalize function with improved timeout handling:

1. **Better Stream Reader Management**: 
   - Added explicit tracking of the stream reader object
   - Ensured reader is properly cancelled in all code paths (success, timeout, error)

2. **Improved Timeout Logic**:
   - Added a `streamCompleted` flag to track when the stream finishes naturally
   - Enhanced timeout error message with actionable user guidance
   - Properly distinguish between timeout errors and other errors

3. **Robust Cleanup**:
   - Added finally block that ensures stream reader is always cleaned up
   - Used try/catch around reader.cancel() to handle expected cancellation errors
   - Cleared timeout ID in all scenarios

4. **Enhanced Error Handling**:
   - Special handling for timeout errors to provide better user feedback
   - Maintained existing error handling for non-timeout scenarios
   - Added user-friendly timeout message with actionable steps

5. **State Management**:
   - Ensured proper state updates even when timeout occurs
   - Maintained consistency of UI state during timeout scenarios

## Changes Made
Modified the `handleFinalize` function in `components/architect/ExpandOverlay.tsx` (lines 550-642) with a more robust implementation that:
- Properly tracks and cleans up stream readers
- Distinguishes between timeout and other error conditions
- Provides clear guidance to users when timeouts occur
- Ensures all resources are properly released regardless of outcome

## Verification
The fix maintains backward compatibility while significantly improving reliability:
- Normal successful completions continue to work as before
- Timeout scenarios now properly terminate and inform the user
- Error cases are handled with appropriate cleanup
- No breaking changes to the component's public interface
